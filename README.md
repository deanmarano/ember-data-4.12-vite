# ember-data-4.12-vite

Vite integration for ember-data 4.12. Provides the `@embroider/macros` configuration and module resolution that `addon-main.js` would normally handle in a classic ember-cli build.

## The Problem

Ember-data 4.12 packages are **V1 addons**. Each package ships an `addon-main.js` that hooks into ember-cli's build pipeline to:

1. Configure `@embroider/macros` with feature flags, deprecation flags, debug flags, environment flags, and package-detection flags
2. Wire up module resolution so that `@ember-data/store`, `@ember-data/model`, etc. resolve to the pre-built code in each package's `addon/` directory

**Vite never executes `addon-main.js`.** When you use `@embroider/vite` to build your Ember app, the macros config is never set, `getOwnConfig()` returns `undefined`, and module resolution fails.

## The Solution

This package bridges the gap with zero patching of published packages:

1. **Macros config** — Replicates the exact config that `addon-main.js` would have built (deprecation computation from `compatWith`, environment detection, package auto-detection)
2. **Resolve plugin** — A Vite plugin that maps `@ember-data/*` imports to the correct `addon/` files, running before `@embroider/vite`'s resolver
3. **Virtual modules** — Provides `ember-data/version` as a virtual module (normally generated by ember-cli at build time)

## Install

```bash
npm install ember-data-4.12-vite
# or
pnpm add ember-data-4.12-vite
```

### Peer Dependencies

- `@embroider/macros` ^1.10.0 (required)
- `vite` ^5.0.0 || ^6.0.0 (optional — only needed for the resolve plugin)

## Quick Start

The `emberData412()` function returns everything you need in one call:

```js
// shared-config.mjs
import { emberData412 } from 'ember-data-4.12-vite';

export const ed = emberData412({ compatWith: '4.12' });
```

```js
// babel.config.mjs
import { ed } from './shared-config.mjs';

export default {
  plugins: [
    ...ed.babelPlugins,
    // your other babel plugins...
  ],
};
```

```js
// vite.config.mjs
import { defineConfig } from 'vite';
import { ember } from '@embroider/vite';
import { ed } from './shared-config.mjs';

export default defineConfig({
  plugins: [
    ...ed.vitePlugins, // must come before ember()
    ember(),
  ],
  optimizeDeps: ed.optimizeDeps,
});
```

The returned object contains:

| Property | Type | Description |
|----------|------|-------------|
| `babelPlugins` | `unknown[]` | Babel plugin array — spread into `babel.config` plugins |
| `vitePlugins` | `Plugin[]` | Vite plugin array — spread into `vite.config` plugins |
| `macrosConfig` | `EmberDataMacrosConfig` | Raw config object for inspection |
| `optimizeDeps` | `{ include: string[] }` | Vite `optimizeDeps` config for pre-bundling |

## Composable API

If you need more control, each piece is available individually.

### `defaultMacrosConfig(options?)`

Returns the full macros config object. You can inspect it, tweak it, or pass it to other tools.

```js
import { defaultMacrosConfig } from 'ember-data-4.12-vite';

const config = defaultMacrosConfig({ compatWith: '4.12' });
console.log(config.deprecations);
// { DEPRECATE_CATCH_ALL: true, DEPRECATE_3_12: false, ... }
```

### `emberDataBabelPlugins(options?)`

Returns a babel plugin array that configures `@embroider/macros` with the correct ember-data config. All `@ember-data/*` packages receive the same config — this matches the real `addon-main.js` behavior.

```js
// babel.config.mjs
import { emberDataBabelPlugins } from 'ember-data-4.12-vite';

export default {
  plugins: [
    ...emberDataBabelPlugins({ compatWith: '4.12' }),
    // other plugins...
  ],
};
```

### `emberDataResolvePlugin(options?)`

Vite plugin (`enforce: 'pre'`) that resolves `@ember-data/*` bare specifiers to the pre-built `addon/` files in `node_modules`.

```js
// vite.config.mjs
import { emberDataResolvePlugin } from 'ember-data-4.12-vite';

export default defineConfig({
  plugins: [
    emberDataResolvePlugin(), // must come before ember()
    ember(),
  ],
});
```

Handles these packages and their sub-paths:

| Package | Entry Points |
|---------|-------------|
| `@ember-data/store` | `index`, `-private` |
| `@ember-data/model` | `index`, `-private` |
| `@ember-data/adapter` | `index`, `-private`, `error`, `json-api`, `rest` |
| `@ember-data/serializer` | `index`, `-private`, `transform`, `json`, `json-api`, `rest` |
| `@ember-data/graph` | `-private` only (no index) |
| `@ember-data/json-api` | `index` |
| `@ember-data/legacy-compat` | `index`, `-private` |
| `@ember-data/request` | `index`, `fetch` |
| `@ember-data/tracking` | `index`, `-private` |

Plus `ember-data` meta-package re-exports and `ember-data/version` (virtual module).

## Options

All APIs accept the same options object:

```ts
interface EmberData412Options {
  // Version compatibility — controls which deprecated code paths are stripped.
  // e.g. '4.12' strips all deprecations introduced at or before 4.12.
  // null (default) keeps all deprecated code.
  compatWith?: string | null;

  // Root directory for package resolution. Defaults to process.cwd().
  rootDir?: string;

  // Enable crypto.randomUUID polyfill. Default false.
  polyfillUUID?: boolean;

  // Include Ember Inspector data adapter. Default false.
  includeDataAdapter?: boolean;

  // Override individual debug logging flags (all default to false).
  debug?: Partial<{
    LOG_PAYLOADS: boolean;
    LOG_OPERATIONS: boolean;
    LOG_MUTATIONS: boolean;
    LOG_NOTIFICATIONS: boolean;
    LOG_REQUESTS: boolean;
    LOG_REQUEST_STATUS: boolean;
    LOG_IDENTIFIERS: boolean;
    LOG_GRAPH: boolean;
    LOG_INSTANCE_CACHE: boolean;
  }>;

  // Override computed deprecation flags.
  // These are applied after compatWith computation,
  // so you can force specific flags on or off.
  deprecations?: Partial<DeprecationFlags>;

  // Override feature flags. Only SAMPLE_FEATURE_FLAG exists in 4.12.
  features?: Partial<{ SAMPLE_FEATURE_FLAG: boolean }>;

  // Override auto-detected package flags.
  packages?: Partial<PackageFlags>;

  // Override environment detection (normally derived from process.env).
  env?: Partial<{
    TESTING: boolean;
    PRODUCTION: boolean;
    DEBUG: boolean;
  }>;
}
```

### Deprecation Stripping

The `compatWith` option controls which deprecated code paths are removed at build time. When you set `compatWith: '4.12'`, any deprecation introduced at or before version 4.12 is stripped (its flag is set to `false`).

```js
// Strip all deprecations through 4.12 — recommended for apps on 4.12
const config = defaultMacrosConfig({ compatWith: '4.12' });

// Keep all deprecated code (default)
const config = defaultMacrosConfig();

// Strip some, keep others
const config = defaultMacrosConfig({
  compatWith: '4.7',
  deprecations: {
    // Force-keep a specific deprecation that compatWith would strip
    DEPRECATE_PROMISE_PROXIES: true,
  },
});
```

For advanced use cases, the underlying utilities are also exported:

```js
import {

} from 'ember-data-4.12-vite';
```

## How It Works

In a classic ember-cli build, each `@ember-data/*` package's `addon-main.js` runs during the `included()` hook to:

1. Read host app options (`emberData.compatWith`, `emberData.debug`, etc.)
2. Compute deprecation flags using `semver.lte(minVersion(deprecatedSince), minVersion(compatWith))`
3. Detect which `@ember-data/*` packages are installed via `require.resolve`
4. Read `process.env` for `EMBER_ENV`, `IS_TESTING`, etc.
5. Register all of this as `@embroider/macros` `setOwnConfig`

The published runtime code in `addon/` directories uses `@embroider/macros` APIs (`getOwnConfig()`, `macroCondition()`, `importSync()`) which read this config at build time to eliminate dead code branches.

This package replicates steps 1–5 outside of ember-cli, then feeds the result into `@embroider/macros`'s `buildMacros()` API so that Vite's babel pipeline can process the macros correctly.
